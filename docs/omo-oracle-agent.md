## 개요

Oracle은 OhMyOpenCode의 **전략적 기술 고문**입니다. 복잡한 분석, 아키텍처 설계, 디버깅이 필요할 때 사용자(또는 메인 에이전트)에 의해 상담됩니다.

---

## 역할 및 정체성

**이름 유래**: 그리스 로마 신화에서 지혜, 신탁, 예얁의 신. 미래를 내다보고 조언하는 전문가입니다.

**정체성**: 읽기 전용 상담 전문가입니다. 코드를 직접 수정하지 않습니다.

---

## 핵심 역량

1. **코드베이스 해체**: 구조적 패턴과 설계 선택지 이해
2. **구체적, 실현 가능한 기술 권고안 제시**: 실제로 구현할 수 있는 권고안
3. **아키텍처 설계 및 리팩터링 로드맵 작성**: 시스템 구조화 및 개선 단계
4. **복잡한 기술적 질문 해결**: 체계적인 추론으로 문제 해결
5. **숨견된 이슈 식별 및 예방 조치 마련**: 발생 가능한 문제 미리 찾기
6. **실행 가능한 답변 제공**: 명확하고 조치 가능한 권고안

```markdown
- API 호출은 기존 패턴을 따릅니다.
```

```markdown
## 요약
마이크로서비스스 아키텍처로 전환할 것을 제안합니다. 이 변경은 서비스 간 독립성을 향상하고, 테스트 용이성을 개선하며, 장기적으로 유지보수 비용을 절감합니다.

## 실행 계획
1. 현재 모놀리식 아키텍처 분석 (`src/services/` 디렉토리)

3. 인터페이스 설계: 공통 `Service` 인터페이스 정의

6. 이행 계획 단계화:
   - 단계 1: 서비스 인터페이스 정의

- 새로운 상태 관리 라이브러리를 도입하기 전에 팀과 논의가 필요합니다.

### 3단계: 나머지 서비스 리팩터링

- 통합 테스트 작성

### 4단계: 통합 및 검증

- 모든 서비스 통합 테스트
```
